📖 Einführung

GhettoGUI ist ein grafisches PowerShell-Frontend für ghettoVCB (ESXi-Backup-Script von William Lam). Es vereinfacht Backup, Restore und Replikation von VMs auf VMware ESXi-Hosts und unterstützt seit Version 8.7.x auch Proxmox VE.

Hauptfunktionen

  • Backup einzelner oder mehrerer VMs (mit Scheduling via Cron)
  • Restore von Backups (inkl. Live-Fortschrittsanzeige)
  • Replikation zwischen Hosts
  • E-Mail-Benachrichtigungen bei Erfolg/Fehler
  • Storage-Wizard (NFS, iSCSI, LVM)
  • ESXi-Update-Workflow (.zip/.vib)
  • Proxmox-Manager (ab 9.0)

Voraussetzungen

  • Windows mit PowerShell 5.1+
  • SSH-Zugang zum ESXi-Host aktiviert
  • ghettoVCB-Script auf dem Host installiert

📑 Tabs & Bereiche

Die GUI ist in mehrere Tabs unterteilt:

Tab Beschreibung
ESXi Hauptbereich für Backup/Restore/Replikation, VM-Liste, Job-Verwaltung
Proxmox Manager 9.0 Proxmox-spezifische Funktionen (API-Login, Backup-Jobs, Storage-Wizard)
Einstellungen Globale Konfiguration, Pfade, E-Mail-Setup

ESXi-Tab Bereiche

  • Verbindung: Host-IP, Benutzer, Passwort, Connect-Button
  • VM-Liste: Checkboxen zur Auswahl der VMs
  • Backup-Optionen: Ziel-Datastore, Rotation, Quiesce, etc.
  • Job-Verwaltung: Jobs speichern/laden/löschen
  • Konsole/Log: Live-Ausgabe der Operationen

💾 Backup

Grundablauf

  1. Mit ESXi-Host verbinden (IP, User, Passwort)
  2. VMs in der Liste auswählen (Checkboxen)
  3. Ziel-Datastore und Backup-Verzeichnis wählen
  4. Optionen setzen (Rotation, Quiesce, etc.)
  5. Backup starten

Wichtige Optionen

Option Beschreibung
VM_BACKUP_ROTATION_COUNT Anzahl der aufzubewahrenden Backup-Generationen
ENABLE_HARD_POWER_OFF VM hart ausschalten, falls Shutdown fehlschlägt
ITER_TO_WAIT_SHUTDOWN Wartezyklen vor Hard-Power-Off
POWER_VM_DOWN_BEFORE_BACKUP VM vor Backup herunterfahren (konsistenteres Backup)
ENABLE_COMPRESSION VMDK-Komprimierung aktivieren

Job-Verwaltung

Jobs werden als *.json gespeichert und enthalten VM-Auswahl, Optionen und Ziel-Konfiguration. In Version 8.7.8 lädt „Job laden" die VM-Liste automatisch nach und setzt die Checkboxen korrekt.

🔄 Restore

Ablauf

  1. Backup-Verzeichnis auf dem Datastore auswählen
  2. Ziel-Datastore für die wiederhergestellte VM wählen
  3. Restore starten (mit Sicherheitsabfrage seit 8.7.8)
  4. Live-Fortschritt im Log beobachten

Neue Features in 8.7.8

  • Live-Kopierfortschritt: Prozentanzeige während des Restore
  • Sicherheitsabfrage: Bestätigung vor Restore-Start
  • Kontextsensitive Popups: Abschlussmeldung mit VM-Name
  • E-Mail-Benachrichtigung: Detaillierte Mail nach Restore
Hinweis: Bei sehr großen VMs kann der Restore lange dauern. Beobachte den Live-Fortschritt und prüfe bei Stillstand Storage-IO und Netzwerk.

🔁 Replikation

Replikation kopiert VMs zwischen ESXi-Hosts. Dies ist nützlich für Disaster Recovery oder Migration.

Konfiguration

  • Quell-Host und Ziel-Host konfigurieren
  • VMs zur Replikation auswählen
  • Ziel-Datastore auf dem Remote-Host wählen

Änderung in 8.7.8

Der Replikations-Dialog verwendet nun „Speichern unter…" statt „Speichern" für klarere Benutzerführung.

🗄️ Storage Wizard

Der Storage-Wizard hilft beim Einrichten von Datastores auf ESXi und Proxmox.

Unterstützte Storage-Typen

Typ Beschreibung
NFS Network File System – einfach einzurichten, gut für Backups
iSCSI Block-Storage über Netzwerk – höhere Performance
LVM Logical Volume Manager – für Proxmox, Disk-Images

Für LVM wird (laut Hinweis im Script) standardmäßig ein Layout für „Disk-Images" vorbereitet.

  • Ungerade KW: Ausführung nur in Wochen wie 1, 3, 5... (Anzeige: „Alle 2 Wochen (Ungerade KW)“).

3. Monitoring & Troubleshooting

Live

Log-Analyse

Das Echtzeit-Logfenster überwacht jeden Schritt von ghettoVCB. Besonders bei großen VMs (z.B. 30 TB) ist hier die Überwachung der Snapshot-Phase und der VMDK-Übertragung entscheidend.

Security

Ghetto-Assassin

Sollte ein Job hängen bleiben, beendet dieses Tool sicher die verwaisten Prozesse auf dem ESXi und räumt temporäre Dateien auf, um den Datastore-Lock aufzuheben.

Achtung bei Groß-VMs: Bei der Sicherung von 30 TB VMs sollte sichergestellt sein, dass die Retention (Vorhaltezeit) den verfügbaren Speicherplatz auf dem Ziel-NFS/Datastore nicht überschreitet. Ein einzelnes Backup dieser Größe benötigt bei 1 GbE ca. 70-80 Stunden – 10 GbE wird dringend empfohlen.

Unterstützte Intervalle

  • Täglich
  • Wöchentlich
  • 2-Wöchentlich (neu in 8.7.8)
  • Monatlich (neu in 8.7.8)

ESXi6 Besonderheiten

BusyBox-Einschränkungen (eingeschränkte sed/grep/date Optionen) werden in den Patch-Skripten berücksichtigt. In 8.7.8 ist „E-Mail und Cron für ESXi 6.0" explizit gefixt.

📧 E-Mail / Benachrichtigungen

Grundprinzip

  • ghettoVCB erzeugt ein detailliertes Log und ruft am Ende ein Mail-Script auf (sendmail*.py)
  • ESXi6 nutzt häufig Port 25 (Fallback) als zuverlässigen Weg
  • ESXi8 kann Port 587 (SMTP Submission) nutzen – abhängig von TLS/Auth

Ports 25 vs 587

Port Typ Typische Anforderungen Empfehlung
25 SMTP oft ohne Auth/TLS (in LAN), sehr robust Für ESXi6/Legacy als Fallback ideal
587 Submission STARTTLS, Auth, Zertifikatsprüfung Auf ESXi8 möglich, TLS-Handling beachten

Wichtig: Fehlerfall vs OK-Fall

Wenn Mails bei „OK" gehen, aber bei „ERROR/WARN" nicht, ist das fast immer ein Payload/Encoding/Linebreak-Thema: Fehlerlogs enthalten oft Sonderzeichen, sehr lange Zeilen oder ungewöhnliche Sequenzen.

Installation

Button „E-Mail-Skript installieren" kopiert/aktiviert das Script auf dem Host. Konfiguration erfolgt über die ghettoVCB-Config (EMAIL_SERVER, EMAIL_SERVER_PORT, EMAIL_FROM, EMAIL_TO, etc.).

🖥️ Proxmox Manager 9.0

Funktionen

  • API Login / Ticket Handling (Get-ProxmoxTicket)
  • REST Requests mit CSRF Token und Cookie (Invoke-ProxmoxApiRequest)
  • Backup-Job erstellen (New-ProxmoxBackupJob)
  • Task-Status & Task-Logs abfragen
  • Storage-Auswahl-Dialoge und Storage-Wizard (u.a. LVM)

Grundablauf

  1. Im Tab „Proxmox Manager 9.0" Host/IP, User und Passwort eintragen
  2. Login – GhettoGUI holt ein Ticket und merkt CSRF Token
  3. Storages auswählen (Dialog) oder Storage-Wizard ausführen
  4. Backup-Job definieren und starten
  5. Task-Polling zeigt Fortschritt; Log-Output wird live ergänzt

Hinweis: Das Script setzt TLS12 und nutzt eine „TrustAllCertsPolicy". In produktiven Umgebungen ist ein korrektes Zertifikatssetup empfehlenswert.

🔧 Fehlerbehebung

1) SSH / Verbindungsprobleme

  • SSH auf ESXi aktiviert?
  • Firewall/Routing OK?
  • Timeout (8.7.8: 60s) reicht bei langsamen Hosts evtl. knapp → Netz/Host-Load prüfen

2) Cron läuft nicht

  • ESXi6: BusyBox-Kompatibilität – keine GNU-Optionen erwarten
  • Prüfe, ob der Cron-Eintrag wirklich gespeichert wurde und ob Pfade stimmen

3) E-Mail: Port 587 funktioniert bei OK, aber nicht bei ERROR

  • Body-Normalisierung: CRLF/Unicode/zu lange Zeilen
  • Größe: große Logs können SMTP Limits sprengen
  • STARTTLS/Auth: bei Fehlern wird ggf. ein anderer Codepfad genutzt
  • Wenn Port 25 zuverlässig ist, nutze ihn als Fallback oder primär (in LAN/Relay-Szenarien)

4) Restore langsam / hängt

  • Live-Log zeigt Fortschritt – wenn er steht: Storage-IO, Netzwerk, Ziel-Datastore prüfen
  • Bei sehr großen VMs: Zeitfenster und Datastore-Performance berücksichtigen

❓ FAQ

Warum fragt ESXi manchmal nicht „kopiert oder verschoben"?

Wenn VMX-UUID-Felder beibehalten werden oder eine VMX-Patch-Routine nicht sauber läuft, startet ESXi ohne Prompt. Das ist normal und wird durch konsequentes Entfernen/Regenerieren der entsprechenden VMX-Keys korrigiert.

Kann ich Jobs wiederverwenden?

Ja. Jobs werden als *.json gespeichert. In 8.7.8 lädt „Job laden" die VM-Liste automatisch nach und setzt die Checkboxen korrekt.
